## The eight features

**#2 Reading ruler + text controls** — Settings rows: Text size (1–3), Space between lines (1–3), Space between letters (0–2) as selects, and a Readable font switch (Verdana/Geneva/Tahoma/Arial system stack; nothing downloaded). All apply as classes on `<body>`; sizes and spacing are scoped to result cards. Reading ruler switch: when on, `#results` gets a `rulerOn` class; pointer movement, touch taps, and keyboard focus inside a result mark the current text block (title, paragraph, or context block) with full strength and pale the other blocks in the results. Until something is pointed at, nothing is dimmed. All values persist in `settings` (`textSize`, `lineSpacing`, `letterSpacing`, `readFont`, `ruler`).

**#3 Low-stimulation mode** — One switch (`settings.lowStim`) adds a `lowstim` class on `<body>`: the palette variables switch to muted values, and every CSS animation and transition is switched off. On first run, if the device reports `prefers-reduced-motion: reduce`, the setting starts on and the switch shows it (guarded try/catch, so a browser without `matchMedia` simply starts off). **Honest partial:** the app's older code calls `scrollIntoView({behavior:'smooth'})` in two places (consent card, checks panel); a script-passed scroll behavior cannot be overridden by CSS, so those two scrolls still glide. Everything the stylesheet controls is still.

**#4 Tap-a-word definitions (Define words)** — A switch (`settings.defineWords`, default off). When on, a plain banner above the results states the mode is on and how to turn it off. A capture-phase click listener on the results intercepts taps inside a result title or summary only — never buttons, never anything outside result text — finds the tapped word with `caretRangeFromPoint`/`caretPositionFromPoint` (selection as a fallback), prevents the link from opening, and shows a small in-card popover: the word, then the first definition from `https://api.dictionaryapi.dev/api/v2/entries/en/<word>`, with a Close button. Any failure — not found, bad response, no network, no `fetch` — shows exactly "No definition found from here." Nothing is invented. While the mode is on, a tap on a saying span gives the definition (Define words takes precedence over Explain sayings for that tap); with the mode off, clicks behave exactly as in v0.7. **Flagged exception to "all other footer text intact":** the footer's privacy sentence claims only the search query leaves the machine. That sentence would be false in v0.8, so one sentence was added to it disclosing the dictionary send (the one tapped word, to dictionaryapi.dev, only in this mode). The honesty standard in the task's own item #5 required it; the parent agent should confirm this edit is acceptable.

**#5 Page preview check** — Every result card gets a Preview button. The panel is built only from data the app already has: the site domain, the full address in plain text, file-type warnings read from the address itself (.pdf, .doc/.docx, archives, direct media files, and the video sites youtube.com / youtu.be / vimeo.com), and a statement that the card's summary is what the search service provided and the page was not opened. It ends with a "Not checked from here:" list — autoplay, advertising share, true page length — stating plainly that those need the page opened and this preview does not open it. No claim is made for any check that was not run. The button toggles the panel; a Close preview button is inside it.

**#6 Plainness label** — `plainnessOf(title, text)` computes average sentence length, the share of words of 9+ letters, and hits against a 42-term built-in jargon list (`JARGON`). Fixed scoring bands produce one of "Written simply", "In between", or "Dense / jargon-heavy", plus a one-line reason built from the same numbers (for example "Short sentences, few long or technical words."). Each card shows "Plainness: <label> — <reason>" in small text. A settings switch (`settings.plainLabels`, default on) hides the labels. Pure text math on text already on screen; deterministic; unit-tested below.

**#8 Set-aside tray** — Integrated into the existing `render(expanded)`: in the focused view, the shown list is still the first three — plus any results the reader has brought back (one line of `render()` changed to allow that). Below the shown cards, a collapsible "Set aside (n) — results below the first three" section lists each remaining result with a one-line reason from data the app has: bounce-shield placement (with the site named), literal-first ordering (commentary ranked below direct answers), or its plain position number in the current order. "Bring back" moves that result into the main list and the tray count drops. Opening the existing "Show more results" view shows everything and the tray is not rendered. Bring-back choices reset when a new search or the demo loads new results.

**#9 Read-aloud of the brief version** — A Listen / Stop bar appears above the results whenever results exist. Listen reads each shown card in order as the title plus the first sentence of its summary — the brief version — using `speechSynthesis`, one utterance per card, advancing on each utterance's end. The card being read gets a visible outline (progression is marked per card, not per sentence; sentence-level marking inside the text was not attempted because re-wrapping sentences would disturb the saying spans from v0.7). The topic recap card gets its own Listen / Stop buttons reading the recap text, including the restated goal. Starting a new search (Search button, Enter, a topic pick-up, or the Demo button) cancels any reading in progress. Where `speechSynthesis` does not exist, the buttons are replaced by the plain line "Reading aloud is not available in this browser." (verified in a no-speech test instance).

**#10 Goal anchor** — A sticky bar above the results: label "I am trying to:", a one-line input ("Write your goal in a few words, or leave this empty."), and a Clear goal button. It persists as `settings.goal`, stays at the top of the page while results are on screen, and the recap card restates it as "Your goal was: ..." with the explicit note that the app does not score results against the goal. Restating only, labeled honestly — no scoring is done anywhere. When no topic is active, the recap area shows the goal line on its own so the restatement is visible outside topics too (the only behavior change to the recap area, and only when a goal is set).

## Uncertainties / notes for the parent agent
- The footer privacy-sentence addition (flagged under #4) is the one deliberate deviation from "all other footer text intact" — it was required to keep the privacy statement true. Everything else in the footer is untouched apart from the v0.8 history sentence.
- Low-stimulation mode cannot cancel the two script-driven smooth scrolls (consent card, checks panel) — noted under #3.
